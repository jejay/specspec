# Keep intentions distinct from revisable conclusions

Build a practical spec-aware development tool that lets engineers and coding
agents keep project intentions distinct from revisable solution choices, navigate
their justifications, and maintain a specification alongside evolving implementation.

Allocate review according to uncertainty, impact, and the user's available attention.
Earlier intentions often merit more scrutiny than later conclusions; when the user
judges an implementation attempt worth its risk and token cost, do not require
additional per-node proposed/accepted sign-offs. Conclusions remain revisable as
implementation and feedback expose new understanding. Git records newness and change.
