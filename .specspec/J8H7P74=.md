# Initialize Git and concatenate packaged project instructions safely

Bundle a static AGENTS.md template with the Python distribution. It explains
relationships, meaningful granularity, shortcut-free ancestry, positive bindings,
owner/tandem/planning/implementation phases and ordinary current-directory commands.

Init requires an available working Git executable. Reuse a containing Git working
tree, including linked worktrees; otherwise run git init in the selected project. Validate the manifesto and instruction target first. Existing repositories
remain usable; initialization never stages, commits or configures identity/hooks.
If Git is absent or initialization fails, report it without publishing a graph or
guide. Git metadata created by a successful git init stays under Git ownership,
including after a later graph-publication failure or recovery.

Create AGENTS.md when absent. Otherwise concatenate the template after the exact
original bytes, with a separating blank line when needed. Reject directories and
symlinks rather than following them or silently omitting the requested instructions.
Stage complete node/guide bytes under .specspec/local, journal originals and intended
results, guard original bytes and exclusively publish absent files. Recovery checks
all states before restoring an amended original or removing newly created files;
external edits stay protected. Empty/local-only canonical directories can be
initialized when no interrupted writer needs recovery. Runtime state is not a node.

Protect .specspec/local through a checkout-local Git exclusion, retaining existing
exclude bytes and leaving project ignore files unchanged.
