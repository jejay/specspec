# State what the product is and ought to be at this point, in positive sentences

Every node says what the product does or ought to do at this point. Behavior, limits and the handling of errors are written as plain positive statements. Requirements say what ought to be, and implementation nodes explain the code that exists and how it is checked. The reasons for a change, the record of test runs and what was removed live in Git: in earlier commits, differences and commit messages. Behavior is stated precisely enough that two implementations of a node would behave alike; what a node means and what is still uncertain are for review to judge.
